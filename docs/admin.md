# Admin 系統管理

第五階段新增「系統管理」頁面，只對目前角色為 Admin 的登入者提供入口。後端每個管理端點都重新驗證 JWT、目前角色與帳號狀態；隱藏前端入口不作為授權依據。

## 功能與端點

| 分頁 | API | 功能 |
|---|---|---|
| 使用者管理 | `GET /api/v1/admin/users` | 依 email、角色、啟用狀態篩選與分頁 |
| 使用者管理 | `GET /api/v1/admin/users/{id}` | 查詢最新使用者資訊 |
| 使用者管理 | `PATCH /api/v1/admin/users/{id}` | 修改角色或啟用狀態 |
| 系統日誌 | `GET /api/v1/admin/logs` | 查詢持久化的應用程式及管理操作日誌 |
| 系統日誌 | `GET /api/v1/admin/logging-status` | 查看日誌佇列、寫入及省略計數 |
| 資料庫狀態 | `GET /api/v1/admin/database` | 連線健康、延遲、版本、資料量及連線池 |
| 資料庫狀態 | `GET /api/v1/monitoring/status` | 既有生成器、批次寫入及 WebSocket 狀態 |
| 命令列管理 | `GET /api/v1/monitoring/websocket` | 查看 WebSocket 開關與連線數 |
| 命令列管理 | `PUT /api/v1/monitoring/websocket` | 獨立開啟或關閉 WebSocket，REST API 持續運作 |
| 即時歷史 | `GET /api/v1/monitoring/history` | 查詢已提交的監測樣本與異常旗標 |

所有列表示範的頁碼從 1 開始，每頁最多 100 筆。未登入回應 401，User／Viewer 回應 403。Admin 停用或角色改變後，既有 Token 會失效，需重新登入。

獨立控制 WebSocket 的指令與重啟後初始狀態設定，見 [WebSocket 控制](websocket-protocol.md#獨立控制-websocket)。關閉不會停止模擬資料生成或批次保存；這是目前程序的執行開關，與使用者角色／狀態的持久化變更分開。

## 使用者與角色

| 操作 | 語意 |
|---|---|
| 查詢 | API 回傳 ID、email、角色、啟用狀態與 UTC 建立／更新時間，介面轉成台灣時間；不回傳密碼雜湊或 Token 版本 |
| 角色 | `admin`、`user`、`viewer`；沿用既有資料讀寫與監測權限 |
| 停用 | 停止帳號登入及既有憑證使用；保留帳號與其建立的資料 |
| 重新啟用 | 帳號可以重新登入，先前已撤銷的憑證不會恢復 |
| 自我保護 | 拒絕改變自己的角色或停用自己，回應 409；相同值的無變更請求不受影響 |
| 無變更 | 不遞增 Token 版本，不產生重複管理操作紀錄 |
| 實際變更 | 更新資料、遞增 Token 版本、寫入操作紀錄，在同一筆交易提交 |

頁面需要明確確認才送出變更。儲存成功、切換帳號或帳號資料被其他管理員更新後，會重新建立編輯表單並清除確認勾選；下一次變更需重新確認。新使用者仍從註冊入口建立，管理員再依需要調整角色；此階段帳號管理採啟用／停用，資料擁有權保持不變。

初始化管理員與其他帳號使用相同的管理規則。Bootstrap 只負責首次建立不存在的 email；如果該帳號之後被另一位 Admin 降權或停用，重新啟動時保留目前角色、狀態、密碼及 Token 版本，不會升權、重新啟用或阻擋遷移服務完成。

PATCH 只接受 `role`、`is_active`，拒絕空物件、`null`、字串形式的布林值及額外欄位。

```json
{"role": "viewer", "is_active": true}
```

更新時會按使用者 ID 順序鎖住操作者及目標帳號，並在取得鎖後再次檢查操作者的角色、啟用狀態與 Token 版本。管理操作不允許修改操作者自身，因此每個成功交易都保留一名啟用中的 Admin；同時互相降級的請求不能繞過此限制。

變更後，目標帳號後續 REST 請求會被拒絕；既有 WebSocket 也會在持續驗證時關閉。前端收到 401 後清除整個 Session。只在畫面顯示警告不能取代這些後端檢查。

## 系統日誌

日誌保存在 MariaDB 的 `system_logs` 表中，可在重啟後查詢已提交的資料。這個頁面查詢的是 DataPulse 應用程式日誌，不是 Docker、MariaDB 或其他容器的原始輸出。

| 種類 | 內容與保存方式 |
|---|---|
| `request` | HTTP 方法、路由格式、狀態碼、耗時、Request ID 及已驗證的操作者 ID |
| `runtime` | 應用生命週期、背景任務、資料庫或 WebSocket 的受控訊息與錯誤類別 |
| `audit` | 操作者、目標使用者、操作名稱，以及角色／啟用狀態變更前後值；與變更交易一起寫入 |

查詢可組合 `level`、`kind`、`request_id`、`actor_id`、`q`（訊息文字）、`start_time`、`end_time`。時間需帶時區，正規化為 UTC，採 `[start_time, end_time)`；固定按 `timestamp DESC, id DESC` 排序。持續新增日誌時，不同分頁請求的內容可能移動，固定結束時間可縮小這個影響。

HTTP 路徑保存 `/api/v1/admin/users/{user_id}` 這類路由格式；未匹配路由顯示 `[unmatched]`。日誌不保存密碼、Authorization、JWT、請求本文、查詢參數、SQL 參數或例外原始文字。錯誤只提供類別，搭配 Request ID 排查。

一般 request／runtime 日誌經有界佇列批次寫入；預設佇列容量為 1,000 筆，寫入批次最多 100 筆，約每秒排空一次。背景工作透過 ORM 定期保留最新 10,000 筆，兩次清理之間可能暫時超過此數量，管理操作紀錄也受此保留上限影響。計數器代表目前程序，重啟後歸零；資料表保留已提交紀錄。

日誌佇列滿載、資料庫長期失敗或程序突然中止時，一般日誌可能無法保存，介面會顯示待寫入、省略與失敗數。管理操作紀錄直接參與變更交易；若無法寫入，角色／啟用狀態變更也會回滾。目前沒有永久稽核封存或外部集中日誌服務。

## 資料庫與管線狀態

| 指標 | 意義 |
|---|---|
| 連線狀態／耗時 | 執行 ORM 查詢的結果與本次探測時間，探測有逾時限制 |
| MariaDB 版本 | SQLAlchemy 已建立連線取得的版本資訊 |
| 資料筆數 | 使用者、啟用使用者、一般資料、即時樣本、系統日誌的已提交筆數 |
| 最新樣本時間 | 資料庫中最新監測事件時間，介面以台灣時間顯示；不是 WebSocket 收到的時間 |
| 連線池 | 本 FastAPI 程序的池容量、閒置、借出、額外連線與逾時設定 |
| 即時管線 | 目前程序的生成、待寫入、已保存、失敗及 WebSocket 連線計數 |

此頁以 SQLAlchemy ORM 及 Engine／Pool 提供的資訊呈現狀態，不執行原生 `SHOW` SQL，也不暴露主機密碼或資料庫連線字串。資料筆數與管線累計的基準不同：管線計數重啟會歸零，MariaDB 的已提交筆數會保留。

管理 API 的 JWT 驗證本身需要資料庫。若資料庫完全離線，請求可能先在認證階段回應 503，前端顯示無法確認登入或服務不可用；不能在無法驗證身分時回傳受保護的資料庫資訊。若認證成功後探測失敗，狀態回應顯示 `unavailable`，不展示上一份資料量。

## 即時歷史

系統管理的「即時歷史」提供前往資料分析的入口，歷史列表集中在「系統產生的監控資料」，所有登入角色可使用。分析頁支援設備 A／B／C、標題、事件 UUID、異常狀態及時間範圍，統計、明細與 Excel 共用條件。原 `GET /monitoring/history` 管理 API 保留 Admin 限定；分析頁使用所有登入者可讀的 `/monitoring/samples`。`is_anomaly=true|false` 省略則包含全部。介面時間使用台灣時間（UTC+8），API／資料庫仍使用 UTC；數值與閾值保留精確小數文字。

異常條件為事件當下的 `value > threshold`；等於閾值屬正常。列表只包含批次 writer 已提交的資料，不會將 WebSocket 端的 `pending` 視為已保存。統計、分頁明細及 Excel 下載都在「資料分析 → 系統產生的監控資料」。

## 驗收順序

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | Admin 登入並開啟系統管理 | 可切換四個管理區域 |
| 2 | 用第二個測試帳號註冊、保持登入 | 初始角色為 User |
| 3 | Admin 將第二帳號改為 Viewer | 需確認；舊登入失效，重新登入後只能讀取 |
| 4 | 停用、再啟用第二帳號 | 停用期間不能登入；啟用後可重新登入 |
| 5 | 查詢 `audit` 日誌 | 可看到操作者、目標及變更前後值 |
| 6 | 查看自己的管理控制 | 不允許自行停用或降級 |
| 7 | 開啟資料庫狀態並重新整理 | 顯示健康狀態、版本、資料量、連線池與管線資訊 |
| 8 | 即時歷史入口前往資料分析，再選異常與時間 | 歷史、統計及匯出皆只包含符合條件的已提交樣本 |
| 9 | User／Viewer 登入 | 沒有管理入口，直接呼叫管理 API 仍回應 403 |

部署會套用 `0003_system_logs` 遷移；保留既有 `users`、`records` 與 `realtime_samples`。測試指令與隔離資料庫清理方式見 [README](../README.md)。
