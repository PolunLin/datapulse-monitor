# 統計分析與資料交換

第四階段沿用現有 REST API、JWT 與資料模型，不新增資料表，也不改變即時事件的持久化語意。

## 資料來源與權限

| 來源／操作 | Viewer | User | Admin |
|---|---|---|---|
| 一般資料 `source=records`：分析、Excel 匯出 | 可 | 可 | 可 |
| 系統監控歷史 `source=realtime`：分析、Excel 匯出 | 可 | 可 | 可 |
| CSV／JSON 匯入一般資料 | 不可 | 可，擁有者為自己 | 可，擁有者為自己 |

分析頁提供「我的資料（新增／匯入）」與「系統產生的監控資料」兩種來源。前者固定傳入登入者的 `created_by`，包含本人手動新增及 CSV／JSON 匯入的記錄；後者查詢所有人共用的設備監控快照。一般資料 API 仍沿用單一工作區共享讀取規則，個人分析範圍不代表新增私人資料權限。匯入不接受 `created_by`，也不寫入 `realtime_samples`。分析、歷史明細與匯出只讀已提交資料，WebSocket 畫面中的 `pending` 事件要等批次提交後才會出現在結果中。

分類使用與資料管理一致的設備 A／B／C 下拉選單，也能選「全部設備」。我的資料以 `category=device-001|002|003` 篩選，系統資料以 `device_id` 篩選；系統樣本的測量分類仍為 `temperature`。既有自由分類可經「指定舊分類」查詢；舊監控樣本使用 `legacy`，不會將舊資料誤標為新設備。

歷史查詢集中在分析頁，依目前來源顯示分頁明細。統計、圖表、歷史列表與 Excel 使用相同的已套用條件；切換來源或設備會立即清除舊結果、下載及頁碼。時間、標題等表單條件提交後才套用，畫面會標示實際查詢條件。即時監控頁保留最近資料及持續推送，透過「查看歷史與分析」帶入目前設備。

## 分析 API

`GET /api/v1/analytics`，需 `Authorization: Bearer <token>`。

| 參數 | 說明 |
|---|---|
| `source` | `records`（預設）或 `realtime` |
| `q`、`category` | 標題文字搜尋、分類篩選 |
| `created_by` | 正整數使用者 ID；僅限一般資料 |
| `device_id` | 系統監控設備 ID；僅限 `realtime` |
| `is_anomaly`、`event_id` | 異常狀態與事件 UUID；僅限 `realtime`，同時套用於統計、歷史及匯出 |
| `start_time`、`end_time` | 必須帶時區，正規化為 UTC；範圍為 `[start_time, end_time)` |
| `interval` | `hour` 或 `day`（預設）；依台灣時間（UTC+8）整點／午夜分組；桶起點仍以 UTC 傳輸，所有日期固定 +08:00（不套用歷史夏令時間） |

回應包含 `source`、`interval`、`summary`、`categories`、`trend`。三種統計區塊皆提供 `count`、`total`、`average`、`minimum`、`maximum`；分類另有 `category`，一般資料為記錄分類，系統資料為設備 ID，前端轉成設備名稱；趨勢另有桶起點 `timestamp`。

- 金額／測量值保持 Decimal，JSON 以字串輸出；平均值為資料庫計算的小數結果。
- 無資料時 `count=0`、`total="0"`，其餘統計為 `null`，分類與趨勢為空陣列。
- 趨勢只回傳有資料的時間桶，不將沒有觀測資料的時段視為數值 0。
- 分類與時間桶各最多 1,000 組；超過則回應 422，請縮小時間／分類範圍或改用每日分組。結果不會靜默截斷。
- 統計由 SQLAlchemy ORM 表達式交給 MariaDB 執行，不把全部記錄載入 Python 再計算；同一次分析使用同一筆讀取交易。

## 批次匯入

`POST /api/v1/record-imports`，使用 `multipart/form-data` 的 `file` 欄位。

| 項目 | 規則 |
|---|---|
| 格式 | UTF-8 CSV（接受 BOM）或 JSON 陣列；副檔名 `.csv`／`.json` |
| 欄位 | 必填 `title`、`value`、`category`；選填 `timestamp` |
| 分類 | 只接受 `device-001`、`device-002`、`device-003`，對應設備 A／B／C |
| 數值 | 有限的 Decimal，最多 12 位整數、6 位小數；JSON 建議用字串 |
| 時間 | ISO 8601 並帶時區；省略時使用匯入時的 UTC 時間 |
| 限制 | 檔案最多 2 MiB、5,000 筆；不接受額外欄位或重複 CSV 欄名 |
| 交易 | 整個檔案驗證成功才寫入，任何一列錯誤都不寫入 |
| 成功 | HTTP 201，`{"imported_count": 2}` |
| 錯誤 | HTTP 422，提供列號、欄位與原因；超大檔案為 413 |

CSV 範例：

```csv
title,value,category,timestamp
設備 A 溫度,25.500000,device-001,2026-11-08T09:00:00+08:00
設備 B 溫度,27.125000,device-002,2026-11-08T10:00:00+08:00
```

JSON 範例：

```json
[
  {"title": "設備 A 溫度", "value": "25.500000", "category": "device-001"},
  {"title": "設備 B 溫度", "value": "27.125000", "category": "device-002"}
]
```

CSV 列號包含表頭（第一筆資料為第 2 列），引號包住的跨行欄位算同一筆記錄；JSON 列號為陣列項目順序（從 1 開始）。錯誤明細位於 `error.details`，包含 `errors`、`total_errors`、`errors_truncated`；最多回傳 100 個明細，避免大量錯誤佔用記憶體。錯誤不回顯整列內容。

匯入 API 採新增語意，相同檔案再次送出會新增另一批。前端避免一般 rerun 重複提交，並在同一個登入 Session 中記住成功匯入的檔案內容摘要，阻擋重複內容；重新登入後不保留此紀錄。目前沒有跨請求冪等鍵。若網路逾時而無法確認結果，先在資料管理查詢是否已寫入，再決定是否重試。

## Excel 匯出

`GET /api/v1/record-exports`，接受與分析相同的篩選參數；`interval` 不改變匯出的原始明細。回應為 `.xlsx`，由 `Content-Disposition` 提供下載檔名。

- 匯出目前篩選條件下的全部明細，不受 CRUD 分頁影響；按 `timestamp`、`id` 升冪排列。
- 單次最多 10,000 筆，超過則回應 422，必須縮小範圍，不產生不完整報表。
- 工作簿含資料明細與 Metadata（來源、條件、匯出時間及欄位語意）。
- 即時資料明細包含 `device_id`、`device_name`、`unit`；`source=realtime` 的分析及匯出可依 `device_id` 篩選，避免混合設備。一般資料來源不接受此篩選。
- **精確數值以文字儲存**，避免 Excel 的數字精度限制；可直接比對原始 Decimal。需要 Excel 數值運算時，請自行決定可接受的轉換精度。
- 時間以台灣時間 ISO 8601 文字（含 `+08:00`）儲存；時間欄名使用 `_taipei`，Metadata 標明時區及同一時區的篩選／匯出時間；文字欄位強制為文字，不會把 `=...` 等使用者輸入當成公式執行。
- Excel XML 無法表示的控制字元或 Unicode 非字元會顯示為 `\uXXXX` 跳脫文字，避免產生無法開啟的檔案；此轉換會記錄在 Metadata。
- 有表頭、欄寬、自動篩選與凍結列；檔案建立在背景執行緒，避免阻塞 FastAPI 事件迴圈。

統計、歷史分頁與匯出是獨立的資料庫查詢；期間若有新增、修改或批次提交，筆數可能改變。使用固定時間範圍可減少差異，但目前不提供跨請求的資料快照版本。

## 驗收流程

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | User 在資料管理上傳 `sample_data/records.csv` | 顯示匯入筆數，列表可找到新資料 |
| 2 | 上傳 `sample_data/records-invalid.csv` | 顯示錯誤列／欄位，整批不寫入 |
| 3 | 開啟資料分析，選我的資料、設備與時間範圍 | 僅包含登入者的新增／匯入記錄，指標、圖表及歷史一致套用條件 |
| 4 | 用不會存在的標題查詢 | 顯示無資料，沒有沿用上一份結果 |
| 5 | 產生並下載 Excel | 明細符合條件，小數與台灣時間完整 |
| 6 | 切換篩選後重新查詢 | 舊下載檔案失效，需重新產生 |
| 7 | Viewer 登入 | 可查看兩種來源、歷史及匯出，不能匯入或修改 |
| 8 | 任何角色切換系統監控資料 | 可依設備、標題、異常狀態、UUID 與時間查詢歷史、統計及匯出 |
| 9 | 即時監控選設備 B，再按查看歷史與分析 | 切到分析頁並帶入系統來源、設備 B；後端持續生成 |

測試指令與隔離資料庫操作見 [README](../README.md)。
